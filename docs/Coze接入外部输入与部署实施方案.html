import json, urllib.request
from server import context_token   # 在 数智链海/ 目录下运行

BASE = "https://shuzhi-lianhai-production.up.railway.app"
SECRET = "9f3c8a41...（与 Railway 一致）"
tok = context_token.sign_context_token({
    "user_id": "u_demo_a", "regions": ["region_a"],
    "snapshot_id": "kb-2023@6a947ff19618",
    "allowed_tools": ["get_company_context"],
}, SECRET, 600)
req = urllib.request.Request(BASE + "/api/v1/tools/get_company_context",
    data=json.dumps({"parameters": {"scode": "002860", "year": 2023}}).encode(),
    headers={"X-Context-Token": tok, "Content-Type": "application/json"})
print(json.loads(urllib.request.urlopen(req).read())["coname"])  # 星帅尔

❗
导入报错「API response schema must be json object/array」的原因与修复： Coze 插件解析器要求每个 operation 的响应体都声明 application/json，且 schema 顶层类型必须是 object 或 array。旧版 tool_openapi.yaml 的响应只写了 description， 所以被拦下。v1.1.0 已为全部 9 个 operation 补齐响应 schema，并附加了这些约定： 请求体改为扁平参数（不再嵌套 parameters）、不使用 oneOf/anyOf/allOf、不使用字符串型响应体； 规格与后端工具注册表的一致性由 tests/test_m5_openapi_spec.py 守护。 重新导入 coze/tool_openapi.yaml（v1.1.0）即可。
⚠️
若仍导入失败：改用最小版 coze/tool_openapi.min.yaml —— 只有 1 个 /api/v1/tools/dispatch operation，工具名走 enum、参数以 JSON 字符串（parameters_json）传入， 完全规避多工具与嵌套传参限制。后端 dispatch 接口已实现（见 STEP 10）。
⚠️
kg_api 经验复刻：kg_api 为规避 Coze 多分支与嵌套对象数组传递限制，设计了 /dispatch 单接口统一分发。本项目两种形态都支持：完整版 8+1 个 operation，或最小版单 dispatch。
STEP 9
鉴权配置：X-Context-Token
插件认证方式绑定工作流变量，实现“每轮 token”
鉴权选「不需要鉴权」+ 节点参数里引用变量AUTH
✅
结论先说：「引用工作流变量」的入口不在插件的鉴权面板里，而在 工作流 → 插件节点 → 参数面板。插件鉴权面板只支持填写固定值，无法逐轮变化； 因此正确做法是：插件鉴权选「不需要鉴权」，把 token 当作普通 Header 参数由工作流节点传值。

为什么可以这样做：我们的 tool_openapi.yaml 已经把 X-Context-Token 声明为每个 operation 的普通 header 参数（不是 OpenAPI 的 securitySchemes），所以导入插件后它会直接出现在节点参数列表里，可以逐轮赋不同值。

步骤界面位置操作
① 插件创建/编辑插件详情 → 鉴权方式选择 不需要鉴权（若你的版本必填密钥，则填任意占位值，反正会被节点参数覆盖）
② 工作流开始节点工作流 → 开始节点新增输入变量：context_token（类型 String，必填，描述“短期上下文令牌”）
③ 插件节点工作流 → 插件节点 → 输入参数找到 X-Context-Token 输入框 → 点输入框右侧的 引用 / 变量选择器 → 选 开始节点 → context_token
④ 其余参数同一参数面板scode / year 等引用 N03/N04 的变量；模型不该改写的参数可设为“模型不可见”
TEXT要引用的变量：context_token
变量名：context_token        # 必须在开始节点以同名声明
类型：String                  # 形如 eyJ...ab12.9f3c...（base64.HMAC，10 分钟有效）
来源：项目后端每轮签发        # server/analysis_service.py::build_workflow_parameters
用途：插件请求 Header X-Context-Token → 后端验签后取 user_id / regions / snapshot / allowed_tools
ℹ️
后端已自动传入（无需你手工拼）：对话网关每轮调用工作流时，parameters 里带 context_token、tools_base_url、data_snapshot、product_version、 allowed_tools、message、page_context、history_summary、preferences。 你只需在开始节点声明同名变量，工作流就能取到值。（已由 tests/test_m2_analysis.py 验证 token 可验签、密钥错误则验签失败。）
⚠️
不要这样做：① 把 token 固定写在插件鉴权里 —— 那样 10 分钟后全量失效，且所有人都能用； ② 把 token 交给大模型当提示词变量 —— 方案 5.2 明确要求 token 由工作流变量直接传给工具请求，不进模型上下文。
STEP 10
插件试跑与 /dispatch 备选
先在插件页验证连通，再进工作流
插件试跑TEST
◈
X-Context-Token 到底是什么？它不是固定值，而是由你自己设定的密钥算出来的一串字符 （形如 eyJhbGxvd2Vk...fQ==.9f3c8a41d0b7...），用来证明“这次调用来自我们后端”并绑定用户/地区/数据版本。 在设定 TOOL_CONTEXT_SECRET 之前，任何 token 都不存在——所以没有现成字符串可以抄，必须先定密钥、再取值。 插件页「试运行」是绕过工作流直接调插件，没有开始节点变量可引用，因此必须手工填这个值。
✅
最简单的办法（免脚本，推荐先用它跑通）：把密钥本身当作 token。
① Railway → Variables 加两项：TOOL_CONTEXT_SECRET = szlh-2026-debug-7f3a91c4（可自定，够长即可）与 ALLOW_STATIC_DEBUG_TOKEN = 1；
② 重新部署；
③ 插件试跑时 X-Context-Token 就填 szlh-2026-debug-7f3a91c4（与密钥一字不差）；
④ 联调结束后删除 ALLOW_STATIC_DEBUG_TOKEN（生产必须关闭），工作流里改用变量引用。
该开关默认关闭；关闭时把密钥当 token 用会返回 403（已有测试守护）。

async function main({ params }) {
  const draft = typeof params.draft === 'string' ? JSON.parse(params.draft) : params.draft;
  const kinds = ['fact','hypothesis','product','checklist','note'];
  const refPrefix = ['ev:','metric:','product:','analysis:','compare:','regional:','company:'];
  const issues = [];
  if (!Array.isArray(draft.answer_blocks)) issues.push('answer_blocks 必须是数组');
  if (!Array.isArray(draft.recommendations)) issues.push('recommendations 必须是数组');
  (draft.answer_blocks || []).forEach((b, i) => {
    if (!kinds.includes(b.kind)) { issues.push(`block[${i}] 未知 kind: ${b.kind}`); b.kind = 'note'; }
    b.refs = (b.refs || []).filter(r => refPrefix.some(p => String(r).startsWith(p)));
    delete b._refs_extra;                      /* 剔除未知字段 */
  });
  (draft.recommendations || []).forEach(r => {
    if (r.product_ref && !String(r.product_ref).startsWith('product:')) {
      issues.push(`${r.id} 产品引用非法，已降为讨论方向`); r.product_ref = null;
    }
    if (!['discussion_first','standard','later','not_applicable'].includes(r.priority)) {
      issues.push(`${r.id} priority 非法`); r.priority = 'standard';
    }
  });
  return { valid: issues.length === 0, issues: issues.join('; '),
           draft: JSON.stringify(draft) };
}
