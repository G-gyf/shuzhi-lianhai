# 前端说明：原文证据光球缺失 与 产品标签映射

> 面向 `web/` 维护者。日期：2026-09-25。
> 结论先行：**AI 引擎侧的引用问题后端已修，前端不必处理**；前端要做的是
> **①让"后端补充的证据球"与"无证据"状态可辨识 ②修一处确定的产品中文名映射错误**。

---

## 一、问题 1：真 AI 路径上「原文依据」光球消失

### 1.1 现象（线上实测）

一次正常提问（`江苏有哪些光伏企业值得关注？`，2023）返回：

| 观测 | 值 |
|---|---|
| `orbs` | 3 个，**全部是 `product` 类型，0 个 `evidence`** |
| `answer_blocks[].refs` | 6 个块**全部为空** |
| `recommendations[].evidence_refs` | 全部为空 |
| `warnings` | 出现 4 条 `[bad_ref] 引用不存在或无权访问，已移除：ev:filter_explanation / ev:item:300827 …` |
| `status` | `validated`（回答与数字都是对的） |

**用户可见后果**：回答正确、数字真实，但**点不出「原文依据」光球，只剩「产品依据」**——
而"每条结论可回溯到年报原文"是本项目的核心卖点。

### 1.2 原因（三层，前端只需知道第一层结论）

1. **模型自造引用**：生成式引擎把工具响应里的**字段名**当引用（`search_companies` 返回里有个
   `filter_explanation` 键，模型就写了 `ev:filter_explanation`；items 里有 `scode`，就写了
   `ev:item:300827`）。合法格式是 `ev:<chunk_id>:<claim_number>:<text_version>` 四段。
2. **后端正确剥离**：`server/analysis_service.py::_ref_ok()` 要求 chunk 真实存在，伪引用被移除
   → 引用全空（这一步是对的，防线有效）。
3. **兜底被抑制**：后端 `_default_orbs()` 只在"草稿完全没有 orbs"时执行；模型自带 3 个 product
   光球 → 兜底不执行 → 页面上没有证据球。

### 1.3 后端已经怎么修的（**前端零改动也能显示**）

`server/analysis_service.py` 新增 `_supplement_evidence_orbs()`：
一轮分析若**一条 evidence 光球都没有**，就从确定性证据包补挂最多 2 条，并打上标记：

```json
{ "id": "orb_ev_sup_0",
  "kind": "evidence",
  "label": "原文依据（后端补充）",
  "summary": "2023 年度披露信号 · 后端从确定性证据包补充，非模型引用",
  "ref_id": "ev:v21_c00020485:3:3f9a1c2e",
  "state": "ready",
  "supplemented": true,
  "main": false }
```

**关键约定**：补挂引用**不会**写回 `answer_blocks[].refs`，所以正文里不会把补挂证据伪装成
模型引用。补挂前每条引用都再过一次 `_ref_ok()`，**保证点得开**。

> 因为是新字段 + 现有 `label()` 会直接使用 `o.label`，**前端不改也能正确显示中文**。
> 下面的改动是"让边界状态更清楚"，不是"不写就坏"。

### 1.4 前端要做的（按优先级）

#### P1-a 区分「后端补充」的光球（`web/assets/orbs.js`）

`button()` 里加一个 class 与悬停前缀，并给类型文案加后缀：

```js
// 在 b.className = 'orb kind-' + kind + ' lit'; 之后
if (o.supplemented) b.classList.add('supplemented');

// b.title 一行改为
b.title = (o.supplemented ? '【后端补充】' : '') + (o.summary || label(o));

// 类型文案一行改为
['orb-kind', KIND_CN[kind] + (o.supplemented ? '·补充' : '')]
```

配套 CSS（`web/assets/chat.css`）——建议用**中性灰**，不要用金色/绿色，避免看起来像"已核实"：

```css
.orb.supplemented .orb-kind { color: var(--txt-soft); }
.orb.supplemented .orb-sphere { opacity: .85; }
```

#### P1-b 空状态：一轮分析没有任何 evidence 球时**不要静默**（`web/assets/chat.js`）

后端已尽量补挂，但以下情况仍可能没有证据球：

- 提问不涉及具体企业（辖域名单纯筛选类问题），
- 该企业当年没有披露信号，
- 补挂前的存在性校验未通过。

现状：`DSHOrbs.render()` 只渲染收到的球；0 个证据球时界面上**没有任何说明**，用户会以为
"这个系统没有证据功能"。

建议在消费 `orbs_ready` 后判断一次，为 0 时在 orb-bar 之前插一条**中性**提示（不要红色、不要感叹号）：

```
本次分析未附可回溯原文证据（可能为辖区名单类问题，或该企业当年暂无披露信号）。
```

#### P2 `label()` 兜底：别把英文键甩给用户

现状：
```js
const label = (o) => PRODUCT_CN[o.label] || o.label || KIND_CN[o.kind] || '查看依据';
```
若后端给出未知 label，会把**英文下划线键**直接显示（这正是问题 2 的表现）。补一层降级：

```js
const label = (o) => PRODUCT_CN[o.label]
  || (/^[a-z0-9_]+$/.test(o.label || '') ? '' : o.label)
  || KIND_CN[o.kind] || '查看依据';
```
含义：`label` 是纯英文键且查不到映射时，退回中文类型名，而不是露出键名。

### 1.5 前端**不需要**改的（已核对，别重复劳动）

- `drawer.js::render()` 已按 `data.kind` 分发 7 类引用；
- `drawer.js::renderEvidence()` 已渲染 `d.warning`，**已覆盖 `stale_text`**
  （"文本版本与快照不一致，定位待复核"）；
- `orbs.js` 已保证同名依据不折叠、`ref_id` 缺失且非 checklist 时禁用按钮、
  超过 5 个提供"展开其余 N 个依据"；
- 抽屉统一走 `/api/v1/references/{ref_id}`，`ev:` 引用后端已支持。

## 二、问题 2：产品光球会露出英文键（确定的 bug，建议本轮就修）

### 2.1 证据

`rules/products.json` 的 `catalog` 有 **15** 个产品键；`web/assets/orbs.js` 的 `PRODUCT_CN`
也有 **15** 条，但**两边对不上**：

| 类别 | 键 |
|---|---|
| 后端有、前端**缺**（→ 直接显示英文键） | `clearing_path`、`guarantee_prequal`、`ma_loan`、`neibaowaidai`、`offshore_cny`、`project_loan`、`settlement_arch` |
| 前端有、后端**没有**（死代码） | `advance_payment_bond`、`export_credit`、`lc`、`ma_finance`、`project_finance`、`rmb_settlement`、`trade_finance` |
| **键对上了但中文名错** | `advance_bond` 写成"保函预授信"（实为**预付款保函**）；`settlement` 写成"跨境结算"（规范名**跨境人民币结算**） |

**线上已经发生过**：2026-09-25 一次真实问答的产品光球 label 是
`account_setup` / `settlement` / `project_loan` —— 其中 **`project_loan` 会直接显示成英文键**。

### 2.2 修法：整段替换 `web/assets/orbs.js` 第 4 行的 `PRODUCT_CN`

名称以 `rules/products.json` 的 `catalog` 为准（现取现用，勿手写）：

```js
  const PRODUCT_CN = {
    account_setup:'账户方案',      settlement_arch:'跨境结算架构',  guarantee_prequal:'保函预授信',
    settlement:'跨境人民币结算',    clearing_path:'清算行网络接入',  hedging:'汇率避险',
    treasury:'工银全球司库',       project_loan:'境外项目贷款',     neibaowaidai:'内保外贷',
    ma_loan:'跨境并购融资',        bid_bond:'投标保函',            performance_bond:'履约保函',
    advance_bond:'预付款保函',     offshore:'离岸账户（OSA/NRA）',  offshore_cny:'离岸人民币融资',
  };
```

> 维护建议：这张表以后应从产品目录**自动生成**（例如构建时由 `rules/products.json` 的
> `catalog` 注入），否则每次加产品都会再漏一次。本次先手工对齐。

## 三、数据契约速查（`orbs` 数组）

| 字段 | 说明 |
|---|---|
| `kind` | 7 类之一：`company`/`evidence`/`profile`/`product`/`compare`/`analysis`/`checklist`。**非法 kind 后端已丢弃**；前端 `orbs.js` 会把未知 kind 当成 `evidence` 渲染，不要依赖这个兜底 |
| `ref_id` | 形如 `ev:…` / `product:…`；点击时**原样**传给抽屉，不要自行拼装或猜测类型 |
| `label` | 可能是**产品键**（需查 `PRODUCT_CN`）或**中文文案**（直接显示） |
| `summary` | 悬停提示 |
| `state` | `ready`/`pending`/`blocked`；非 `ready` 时按钮禁用 |
| `supplemented` | **`true` = 后端补充的确定性证据，不是模型引用**（新增字段） |
| `main` | 前 5 个为 `true`（后端 `MAX_MAIN_ORBS = 5`） |
| 数量上限 | 后端最多返回 12 个 |

## 四、验收清单

### 浏览器

1. 企业详情页提问 → 回答下方出现光球；
2. 若本轮引擎没给证据 → 出现带「**（后端补充）**」字样的原文球，点击能打开年报原文并高亮；
3. 产品球**全部显示中文名**，页面上不应出现任何英文下划线键；
4. 辖区名单类问题（无具体企业）且无证据球时 → 看到空状态提示，而不是一片空白；
5. 抽屉里若文本版本不一致 → 看到 ⚠ 提示（已支持，回归确认即可）。

### 接口自检

```bash
curl -s 'https://shuzhi-lianhai-production.up.railway.app/api/v1/analyses/<analysis_id>' \
  -H 'Authorization: Bearer demo-token-region-a' | python -m json.tool
```
看 `draft.orbs`：应至少有一个 `"kind": "evidence"`；补挂的那条应带 `"supplemented": true`。
