## 2. 研究样本数检查与统一方案

### 2.1 当前报告的内部关系

`技术链/出海预测/docs/当前基准/企业出海需求指标验证.md`第8行写“273企业-年片段”。第22—23行矩阵为TP=66、FP=15、FN=3、TN=259，合计343。

用这四个数计算，确实得到Accuracy94.7522%、Precision81.4815%、Recall95.6522%、F1=88%、Kappa=0.846692。因此报告指标与343矩阵内部一致；问题是**343条矩阵缺少已找到的逐条底稿，而且与现有478条底稿重算不一致**。

不能只把273改成343然后称已核实，也不能因矩阵可算出指标就认为模型效果已得到真实数据验证。

### 2.2 273的可复现来源

归档的 `v1_keyword_llm_rule_478`、`v2_quote_recovery_478`、`v3_cleaned_claim_retention_478` 的 `summary.json` 中，`within_keyword_pool`矩阵均合计273；`end_to_end_all_478`均合计478。

- 更早baseline关键词池为344，其TP=66、FP=15、FN=9、TN=254，与报告343矩阵也不同。

可确认“273存在于历史候选池”。无法仅凭文件证明报告作者具体从哪一步复制而来，因此“旧口径混写”为有证据支持的解释，不断言编辑过程。

## 3. 109与88的窗口样本差异

### 3.1 两套规则完全复现

旧探查脚本 `_probe_data_quality.py` 明确使用：

```python
has_demand = overseas_demand == 1
no_footprint = (overseas_sub_count.fillna(0) == 0) & (overseas_rev_share.fillna(0) <= 0)
```

该规则得到109个企业—年、61家企业。

改为两个字段都有观测且明确为0：

```python
has_demand = overseas_demand == 1
no_observed_layout = (overseas_sub_count == 0) & (overseas_rev_share == 0)
```

得到88个企业—年、47家企业，与当前first数量一致。

| 差异类型 | 数量 |
|---|---:|
| 子公司数缺失、海外收入为0 | 14 |
| 子公司数为0、海外收入缺失 | 7 |
| 两字段均缺失且被旧规则纳入 | 0 |
| 合计 | 21 |

不是样本年份变化，不是行业扩张，也不是“新国别as-of修复”导致。981个完整标签需求企业—年中，109/981=11.11%，88/981=8.97%；比例必须与分母及完整性一起说明。

### 3.2 当前代码仍有一个状态问题

当前用`(value or 0)`，pandas的NaN并不会可靠变成0。这使上述21条没有进入first，但它们接着被归为15条expansion和6条new_country。

因此不能说“缺失布局状态已完整处理”：数值展示可以是待核实，但窗口分类仍可能给出确定类别。981个需求企业—年中共有38条至少一个布局字段缺失，需结合已知正值判断，不是38条全部都必须归未知。

建议采用显式三态：

- 任一布局指标明确大于0：有布局依据；保留另一指标缺失说明。
- 两指标明确为0：当期无已观测布局。
- 无正值证明且有指标缺失：布局未知。

新国别判断另标注依据是“既有子公司国别记录”，缺记录不能被无条件解释为从未进入该国。

### 3.3 “首现”不是当前已验证含义

47家符合first的企业中，21家只出现1年、15家出现2年、7家出现3年、4家出现4年，合计88企业—年。因此当前标签不是每家只出现一次的“首次线索”。建议先称“有需求且当期未见布局”，若需要首现，另计算首次披露日期/样本首次年份并注明左截断。

### 5.1 名单截断被写成总数

当前实际雷达983企业—年，275家去重企业；默认接口只返回200条，涉及107家企业。页面用`d.items.length`写“共200个出海需求企业—年”，缺少真实total。

建议返回`total_firm_years`、`total_firms`、`page_size`、`items`和筛选范围；页面显示“983条企业年度记录，涉及275家；当前显示200条”。若默认改最新年，2023为237条，仍超过200，仍需分页。

### 5.2 981与983并不代表两家新增企业

981是面板完整标签有需求的企业—年；983是有需求主张且当前被应用纳入雷达的企业—年。多出两条：

| 企业代码 | 年份 | 当前情况 |
|---|---:|---|
| 301187 | 2022 | 已抽出2条部署、1条意图，但年度标签未完成 |
| 688223 | 2023 | 已抽出2条部署、3条意图，但年度标签未完成 |

这两条可作为“部分证据线索”保留，但必须独立状态，不能称已完成研究标签，更不能称光伏新增企业。建议正式统计与探索名单分别计数。

### 5.3 行业筛选语义

行业标签定义为“317家电气设备＋其中37家光伏”。但选“电气设备”时，代码排除了光伏，返回873企业—年；选光伏为110，两者合计983。

建议把选项命名为“全部样本 / 光伏 / 非光伏样本”，或保留电气设备总集并明确嵌套筛选。以用户本次范围，不需要继续显示待扩行业。

### 5.4 展示上限与去重单位

- 23,718是主张总数，4,067才是需求主张；2,593个正向文本块（部署1285＋意图1308）也不是4,067个独立机会。
- 同一事件可跨文本、跨年度重复披露，当前没有事件级去重；“主张条数”不能称“项目数/商机数”。
- 企业详情最多60条当前信号、历史最多8条，子图最多30条；应明确展示数与总量，避免让“没显示”被理解为“不存在”。
- 公司与年度必须分开统计；当期为0与历史从未出海不是同一概念。

## 6. 热度、强度分、能力评分现在有没有问题

三者是不同指标，不能笼统说“评分有错”。

### 6.1 产业热度：计算成立，范围和解释有问题

当前光伏主链：37家中35家在2018—2023任一年有需求主张，35/37=94.59%；前端四舍五入显示95%。253部署＋303意图=556条主张。

这些数可复现，没有发现算术错误。但：

- `/api/segments`没有省份或年份参数，热度始终是全期样本；名单筛选变化时热度不跟随。
- “产业链出海热度”容易被理解为当前出海率或产业传导，而实际是累计需求披露覆盖比例。
- 光伏2023年有需求企业31家、主张167条，不能与全期35家、556条混读。年度比例分母还应取当年有覆盖的企业，不机械沿用37。
- 分类描述“硅料硅片→组件→逆变器→辅材”不能作为真实交易线性链证据。

最小修正：标题改“2018—2023样本累计需求披露概览”，保留35/37与556但明确含义；或者让统计接口真正随名单条件重算。两种都合理，推荐后一种用于客户经理日常筛选。

### 6.2 信号强度：公式按设计运行，属于启发式规则

公式：`2×部署主张数＋意图主张数＋硬锚点数＋min(方向数,3)−1`。

目前没有发现该公式执行与文件定义不一致。需明确：主张多可能因披露更长或重复，并不自动意味着业务价值更高；权重未经营销结果校准；不是转化概率。

前端切换“强度分优先”时后端排序改变，但说明仍固定写“窗口优先”，这是展示文案错误，修正文案即可。是否更改权重属于产品选择，本次不建议无依据重设。

### 6.3 能力评分：跨年参考集确实影响结果

当前原始指标按选定年度读取，但分位参照全部2018—2023企业—年；同一企业多个年份参与分布，历史评分会使用未来分布。

只把参考分布改成同年、其余权重和阈值不变，复算1,594条记录：

- 54条（约3.39%）分级发生变化。
- 最大绝对分差0.038（评分0—1）。
- 说明影响不是纯文字问题，但也不应夸大为全部评分失效。

建议用同年现有电气设备样本为参考集，并返回reference_year、reference_n、missing_dims。光伏子样本可另提供比较视图，不能悄悄改变参考集。

### 6.4 权重与集中度说明

6维配置权重之和为1.10，但代码除以可得权重和，评分不会因此超过1。这不是“总分计算错误”，而是应公开实际权重：完整情况下约22.73%、18.18%、18.18%、13.64%、18.18%、9.09%。

简报写死“样本中位32%”。全期实际31.745%，四舍五入为32%，所以不是无依据数字；但年度中位不同，2023为34.35%，2018为29.50%。应动态读取并说明参考年度。

“前五大集中度高”不等于“对单一客户依赖高”；前五大合计低于50%也不能直接断言风险“可控”。建议显示中性事实及需核实的客户稳定性问题。

## 7. 供应链是不是已经按建议实施

**大方向部分一致：量化数据已接入，也没有建成全量实名网络。但当前实现还超出了单纯结构画像，需要收敛表述与边的生成条件。**

### 7.1 已有且可以保留

- 前五大客户、供应商及占比明细。
- 客户与供应商集中度、HHI等结构指标。
- 已有数据中有限的网络记录，若展示则明确来源、年度及覆盖。
- 原始匿名名称可展示为“第N大客户/供应商”，不应补造身份。

### 7.2 当前还没有完全做到的部分

| 现状 | 问题 | 最小修正 |
|---|---|---|
| 前端写“二跳传导链” | 关系记录不能证明需求或风险传导 | 改“已有网络关系样例”，未核实则默认折叠或不放主演示 |
| named_customer锚点直接生成SELLS_TO | 锚点可能是泛称、计划合作、无关语句 | 未核实者改“文本提及的客户线索”，不直接作为已发生交易边 |
| 文本客户关系不按年 | 存在未来文本倒灌 | 选定年度/截至年度过滤并显示时间 |
| 名称国别识别即标境外 | 公司名称的字串可能误命中 | 改“名称出现国别线索”，正式境外属性需证据核实 |
| 无关系时写“该企业未披露” | 本地没收录不等于企业没披露 | 改“当前数据未收录” |
| 海外客户占比列名称过宽 | 实际只加总前五大中名称识别成功的部分 | 改“前五大中国别线索客户占比”，核实后才称已识别境外客户占比 |

具体证据：1,381条named_customer主张中，1,162为已有行为、162为经营部署、55为出海无关、2为口号；代码没有据此筛除不可靠交易边。时态还包含162条future，不能当全部已成交关系。

本次发现一个可复现国别误命中：`上海顺斯德国际贸易有限公司`被geo_extract识别为德国，因为名称中的“德国际”包含“德国”字串。采购表中有3条此名称记录被标overseas=true。这不能支持“德国供应商”判断；已有smoke主要验证销售侧和若干排除词，未覆盖该情况。

销售侧现有10条名称国别命中、涉及3家样本企业，不能称全面核实境外客户。采购/客户全量记录并非全部都只有“客户一”这类文字，但非匿名外观也不等于可连接的已核实主体。

### 7.3 推荐本期最小方案

保留结构画像和可核查明细；匿名对象只作行内排序标识；文本提及单列为线索；不展示“传导”结论；对少量实名候选保留人工核实入口。把完整企业关联查询放到银行授权数据扩展，不为此扩采全量供应链。
