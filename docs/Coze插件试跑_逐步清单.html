Coze 插件试跑 · 逐步操作清单

从「插件已导入」到「试跑返回 200」。每一步只做一件事，含填什么、期望看到什么、失败怎么办。
开始前 · 先搞清那个值是什么

你要填的 X-Context-Token 是什么？它是后端认人用的「通行证」：Coze 插件每次调用我们后端，后端要确认「这是自己人」。

本轮调试期，你就填你在 Railway 里给 TOOL_CONTEXT_SECRET 设的那个值，一字不差。

# 三个值必须完全一样（大小写、空格都要一致）
Railway Variables:  TOOL_CONTEXT_SECRET       = G-KEY      ← 你设的密钥
Railway Variables:  ALLOW_STATIC_DEBUG_TOKEN  = 1          ← 必须加，否则密钥不能当通行证用
Coze 插件试跑:      X-Context-Token            = G-KEY      ← 填一模一样
ℹ️
正式跑工作流时不需要手工填——后端每轮自动签发通行证并通过工作流变量传给插件（方案 5.2）。手工填只用于「插件试运行」这种绕过工作流的场景。
① 后端（Railway）· 3 步
STEP 1
加 2 个环境变量
Railway → 你的项目 → Variables → New Variable
变量名值作用
TOOL_CONTEXT_SECRET你自己的密钥，例如 G-KEY（够长即可，不要有空格）签发/校验通行证
ALLOW_STATIC_DEBUG_TOKEN1（必须是 1，不能是别的）允许把上面这串密钥直接当通行证用（免脚本）
⚠️
修改变量后 Railway 会自动重新部署，等 1—2 分钟，部署日志出现 Application startup complete 才算生效。不重新部署，变量不会起作用。

上线前：删掉 ALLOW_STATIC_DEBUG_TOKEN（默认关闭，删掉后密钥不能当通行证用，工作流不受影响）。

STEP 2
确认部署的是最新版本
Railway → Deployments

看最新一条部署的 commit 是不是 8bb0017 或更新的提交。不是就点 Redeploy。

ℹ️
本站的接口只有在部署完成后才存在。旧版本没有 /api/v1/tools/dispatch，也不认识 ALLOW_STATIC_DEBUG_TOKEN。
STEP 3
自测后端（这一步能定位 90% 的问题）
在你自己的电脑上跑一条命令

先测服务是否活着：

# 浏览器直接打开这个网址即可
https://shuzhi-lianhai-production.up.railway.app/api/health
# 期望：{"status":"ok","kb":"kb-2023","snapshot_id":"kb-2023@..."}

再把下面命令里的 G-KEY 换成你 STEP 1 设的密钥，运行：

# PowerShell（Windows）
curl.exe -s -w "`nHTTP %{http_code}`n" -X POST `
  https://shuzhi-lianhai-production.up.railway.app/api/v1/tools/resolve_company `
  -H "X-Context-Token: G-KEY" -H "Content-Type: application/json" `
  -d '{\"query\":\"002860\"}'
结果含义下一步
HTTP 200 且出现 星帅尔后端完全就绪，通行证有效直接去 ② 配插件
HTTP 403密钥不匹配，或 ALLOW_STATIC_DEBUG_TOKEN 没生效核对密钥是否一字不差；确认变量已加且已重新部署
HTTP 503没配 TOOL_CONTEXT_SECRET回到 STEP 1
连不上/超时域名不对或服务没起来Railway → Settings → Networking 复制 Public Domain
✅
只要这条 curl 返回 200，后端就没问题了，剩下的都是 Coze 插件配置的事。
② Coze 插件 · 3 步
STEP 4
确认插件的「服务器 URL」
Coze → 工作空间 → 插件 → 你的插件 → 编辑

服务器地址必须是线上域名，不能留着占位符：

✅ 正确  https://shuzhi-lianhai-production.up.railway.app
❌ 错误  https://<项目后端域名>        # 早期版本规格里的占位符，必须改掉
❌ 错误  http://127.0.0.1:8000           # Coze 云端访问不了你本机
❗
如果这里还是占位符，试跑一定失败（连不上），而且报错信息通常是「调试未通过」而不给细节。这是最常见的坑，先查这里。
STEP 5
鉴权方式选「不需要鉴权」
插件详情 → 鉴权方式

选 不需要鉴权。原因：通行证已经在接口规格里声明成了一个普通 header 参数（X-Context-Token），它会直接出现在试跑面板的参数列表里，由你逐次填值；插件的「鉴权」设置只支持固定值，不适合每轮变化。

STEP 6
试跑面板里，每个字段填什么
点插件里的某个工具 → 试运行
字段填什么
X-Context-Token（必填，每个工具都有）你在 STEP 1 设的密钥原值，例如 G-KEY
query（resolve_company 必填）002860
scode（get_company_context / get_rule_candidates 必填）002860
year（可选）2023
evidence_ref（get_evidence 必填）先跑 get_company_context，把它返回里的 signal_refs[0].evidence_ref 整串粘进来
scodes + year（compare_companies 必填）["002860","300670"] + 2023
tool（dispatch 必填）get_company_context，并在 parameters_json 填 {"scode":"002860","year":2023}
其余（province/industry/direction/service_focus/country/page…）可留空；填的话按下拉选项或示例值：江苏省、光伏、capacity_production、settlement
ℹ️
空着不填的参数不要紧，后端会用默认值（例如 page_size 默认 20）。
③ 点试运行 · 3 步
STEP 7
先用最简单的工具打通：resolve_company
只填两个字段，最容易成功
X-Context-Token = G-KEY
query           = 002860

期望结果（右侧 Response 里）：

{"ok": true, "matches": [{"scode": "002860", "coname": "星帅尔", ...}]}
⚠️
如果显示「调试未通过」又不给原因：先回 STEP 3 跑那条 curl。curl 成功 = 后端没问题，问题在插件 URL 或字段；curl 失败 = 后端配置问题。这样一次就能分清。
STEP 8
再逐个跑其余工具
按 STEP 6 的表填字段，token 每次都填同一个值
工具期望（用示例值）
get_company_contextconame=星帅尔，含 signal_refs、rule_candidates
get_evidence返回原文 text 与 spans，status=ok
search_companiestotal=45（江苏省+光伏+产能部署）
compare_companies两家同年度对比表 + compare_ref
get_rule_candidates候选服务列表（含 rule_id、product_ref）
search_product_knowledgetotal=7（service_focus=settlement）或 15（不填条件）
search_regional_knowledgetotal=1（A 区；这是合成示范资料）
tools_dispatchresult.coname=星帅尔
STEP 9
试跑通过后做什么
回到工作流，把手工值换成变量
  1. 工作流 → 开始节点新增输入变量 context_token（String，必填）。
  2. 工作流 → 插件节点 → 输入参数：把 X-Context-Token 的值改为 引用 → 开始节点 → context_token。不要再手工粘贴。
  3. 后端每轮对话自动签发该令牌并随入参传入（已实现，无需你操作）。
  4. 上线前删掉 ALLOW_STATIC_DEBUG_TOKEN。
排查 · 报错对照表
现象原因处理
调试未通过，无任何提示插件服务器 URL 是占位符，或域名写错STEP 4 改成线上域名（必须 https）
403 context_token 无效或已过期填的值 ≠ 后端密钥；或 ALLOW_STATIC_DEBUG_TOKEN 未生效STEP 3 用 curl 验证；核对变量并重新部署
403 且提示「该值与本服务的 TOOL_CONTEXT_SECRET 相同，但静态调试模式未开启」值对了，但开关没开加 ALLOW_STATIC_DEBUG_TOKEN=1 并重新部署
503后端没配密钥加 TOOL_CONTEXT_SECRET
409令牌里的数据快照与线上不一致（正式令牌才会遇到）用 scripts/make_token.py --base-url <域名> 重签
404路径写错（例如把 /dispatch 写成 /tools_dispatch）dispatch 的路径是 /api/v1/tools/dispatch
400 且提示「未知工具」dispatch 的 tool 值不在枚举里照 STEP 6 的枚举值填（英文下划线）
附 · 为什么 kg_api 没有这个「通行证」

kg_api 用的是一个静态 API Key（X-API-Key: KG2025-...）：在插件里填一次固定值，所有请求都用它。之所以够用，是因为那个服务只是只读地查知识图谱，不区分「谁在问、哪个辖区、哪份数据快照」。

本项目不同：通行证里必须带上经理身份、辖区范围、数据快照版本、允许调用的工具，还要求短期有效（方案 5.2 明文要求「每轮生成短期 context_token，不信任模型传来的地区ID」）。所以正式路径不能用一个固定字符串。

但调试期我把它变回了 kg_api 那样的体验：打开 ALLOW_STATIC_DEBUG_TOKEN=1 后，密钥原值就是通行证，填一次即可——等同于 kg_api 的静态 Key。

维度kg_api数智链海（本调试模式）数智链海（正式运行）
填在插件里的值固定 API Key固定密钥（=通行证）不填，由工作流变量传入
携带身份/辖区否用默认演示身份是（当前经理与辖区）
有效期长期长期（调试）10 分钟，到期自动换新
数据快照绑定否否是（不一致返回 409）
