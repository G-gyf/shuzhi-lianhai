02

出海全周期三阶段：全系统统一口径

唯一定义与判别规则在 rules/stages.json，界面、接口、推理链、简报一律按此表述。

T0
筹备期
判别：所选年度存在出海需求信号，且其中不含任何落点类信号。
提前 1—2 年 · 尚未形成可识别落点
典型信号：市场调研、认证准入、本地团队、渠道铺设、研发本地化
营销：先于同业建立关系，锁定结算与保函
T1
落地期
判别：所选年度存在出海需求信号，且其中至少 1 条为落点类信号。
临近落地 · 已出现明确落点
典型信号：产能建设、项目基地、投资并购、拟设境外主体、工程承包
营销：融资与保函切入，额度投放精准对象
T2
存量期
判别：存在海外布局——海外子公司数 > 0，或海外收入占比 > 0（任一项即可）。
已出海 · 越过窗口期
典型依据：海外子公司名录、海外收入占比
营销：从存量中寻找结算融资不在工行的挖转机会
出海前窗口期 ＝ T0 筹备期 ＋ T1 落地期 企业首次在公开披露中表达出海部署或意图（事前），到实际完成落地动作——设立海外主体、形成海外收入（事后）——之间的时段。 窗口期企业＝尚未出海或布局未成熟的企业。
T2 存量期 不属于窗口期 已越过窗口期，不参与窗口期名单，单列为存量挖转入口。 存量企业＝已出海但结算融资不在工行的挖转对象。 两个名单互斥、不重复计数。
落点类信号是区分 T0 与 T1 的唯一判据，命中任一即成立：需求方向属于「产能建设」「投资并购」， 或执行锚点类型属于「项目/基地」「产能/设施」「境外主体」「投资/合同」。
口径分层：从全部主张到三阶段
层级数量说明
全部主张23,718抽取结果全集
出海需求信号4,067满足出海需求判定条件的子集，进入三阶段归类
T0 筹备期信号3,295信号中不含任何落点类信号
T1 落地期信号772信号中至少 1 条为落点类信号
不计入任何阶段19,651既不构成出海部署准备、也不构成落点部署的表述，仅作内部过滤
窗口期（T0/T1）覆盖 983 个企业-年：T0 筹备期 591、T1 落地期 392。 T2 存量期对应已有海外布局的 1,232 个公司-年，其中未落在窗口期内的进入存量挖转名单。
与「窗口布局细分」的关系（两个正交维度）
  • 三阶段回答「企业走到哪一步」：T0 筹备 → T1 落地 → T2 存量
  • 窗口布局细分回答「既有布局到什么程度」：first（当期未见布局）／new_country（新国别进入期）／expansion（出海扩张期）／layout_unknown（布局未知）／label_incomplete（标签不完整但已有需求线索）
  • 两个维度组合使用：例如「T1 落地期 · 新国别进入期」表示已出现落点且目标国别为新增
强度分（描述所选年度披露强度，不是出海概率）：
2 × 落地期信号数 + 1 × 筹备期信号数 + 硬锚点数 + min(出海方向数, 3) − 1
名单排序：窗口布局细分（first 优先）→ 阶段（落地期优先）→ 强度分 → 年份。

处理流程与资产映射

快照机制
  • 知识库按版本打包（kb-2023），快照 ID 为内容哈希
  • 接口携带快照 ID，保证结论与原文一一对应
  • 建库先写临时文件并校验，再替换快照
证据定位链路（零新增成本）
  • 信号表 evidence_start/end → chunk 表原文 → 前端高亮区间
  • 每条主张标注 is_demand 与所属阶段
  • 推理链与简报的每条建议携带 rule_id / signal_id / evidence_id
行业口径：「储能与电源」是项目合并分组（电池／电机／其他电源设备），非申万原生行业名； 行业标签为静态展示，不代表 2018—2023 各年度当时的行业归属。 页面写「样本内光伏 37 家；外部分类名单 74 家」，这是交集与外部规模，不是完成率。

计算模块（三阶段判别、排序、评分卡、推理链）内置服务端。网页确定性接口为 /api/*；对话工作台为 /api/v1/*（Bearer 令牌鉴权，服务端注入辖区，不由 JSON 自报）。下表为现行实际路由，共 31 个。

06

关键设计决策

① 三阶段按「落点」判，不按抽取标签判
  • 底层文本抽取标签只用于筛选出海需求信号，不作为对外口径
  • 把某个抽取标签直接等同于某个阶段，会错分约 28% 的需求信号
  • 判别规则集中在 rules/stages.json，单一事实来源
  • 由测试锁定：对外输出出现旧标签即失败
② 窗口期与存量期分成两个入口
  • 窗口期名单只出 T0/T1；T2 走 /api/stock 单独入口
  • 两个名单互斥、不重复计数：当年仍有新增出海需求的企业归 T0/T1
  • 存量判据可核验：海外子公司数 / 海外收入占比逐行返回
③ 计算全部在服务端
  • 地区侧只拿结果（名单/画像/推理链），不传算法——对应「地区零算力」诉求
④ 图存储：当前 SQLite，Neo4j 仅设计预留
  • 现行实现为 SQLite 证据子图；Neo4j 不属本项目交付范围，已移除「设 NEO4J_URI 自动切换」运行分支
⑤ 推理链结构化
  • 规则引擎输出 JSON 步骤列表，前端展开；LLM 仅做简报文字润色
⑥ 知识库版本化
  • 快照命名（kb-2023）+ 快照 ID（内容哈希），接口携带版本；结论永远对齐对应年报版本
⑦ 供应链三层定位
  • 全量实名供应链与多跳关联查询 = 后续规划；demo 用 CSMAR 结构化量化边（单跳画像）；产业协同叙事用行业分组出海热度
⑧ 七细分行业口径
  • 不扩样：现有 317 家样本内按申万代码归并为七个细分；光伏 37/74 是「交集 / 外部规模」，不是完成率

框架评估结论

站得住的设计
  • 中心生产 + 边缘消费：符合银行 IT 现实，地区零算力
  • 三阶段口径单一事实来源：定义、判别规则、营销动作集中在 stages.json，界面与接口不分叉
  • 窗口期与存量期分离：口径边界诚实，两个名单互斥不重复计数
  • 知识库分离：原文/信号/特征/规则 + 供应链库，各司其职
  • 规则引擎做计算、推理链结构化、证据锚点可回溯
  • 七细分行业 + CSMAR 供应链量化边：行业分组贯通名单与详情
需补强的四点
  • 生成式 AI 引擎可用性：已完成——扣子编程项目可连通，健康检查改为真实探活；并新增冷启动容错（warming 语义 + 自动重试 + 后端保活 + 页面预热）
  • 鉴权 + 辖区隔离：演示身份可用、隔离已验收；行内身份系统接入位已预留，不属本项目实现目标
  • 推理链不用 LLM 自由文本：结构化 JSON + 逐步展开（已定）
  • 辅助判断定位：分级输出 + 「不替代人工尽调」标注（已定）
口径演进说明：v1.3 及以前采用「窗口期二分 + 筹备/落地分层 + 底层抽取标签」的混合表述； v1.4 统一为出海全周期三阶段，底层抽取标签收敛为内部筛选依据，不再出现在任何对外口径中。 因阶段判别基础由标签改为落点，强度分与名单排序相对 v1.3 有变化，历史截图与简报数字需按 v1.4 重出。
