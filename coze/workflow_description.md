# 数智链海出海助手 · 工作流说明（人话版）

## 一、一句话描述（可直接粘到 Coze 工作流的「描述」字段）

> 数智链海出海助手：客户经理用一句话提问，它自动判断你想做什么（找企业 / 解释企业 / 做对比 / 出拜访方案），
> 从数据库和产品资料里查事实，输出带依据的分析与建议。企业名称、数字、原文一律来自受控数据库，不编造。

## 二、它接收什么（开始节点变量）

| 变量 | 谁填 | 说明 |
|---|---|---|
| `message` | 调用方（必填） | 经理的这句话，例如“这家公司值得关注什么？” |
| `page_context` | 调用方 | 当前页面上下文（企业代码、年份）。在企业详情页提问时自动带上 |
| `history_summary` | 调用方 | 前几轮对话摘要，用于理解“第二家”“它”这类指代 |
| `preferences` | 调用方 | 经理偏好，例如重点看结算、不考虑融资 |
| `context_token` | **后端每轮自动签发**（必填） | 通行证：证明请求来自本系统，并绑定经理身份、辖区、数据版本 |
| `data_snapshot` `product_version` `tools_base_url` `allowed_tools` `max_tool_calls` `max_compare_companies` | 后端自动带 | 数据版本与调用限制 |

> 手工试跑时：`message` 填一句话，`context_token` 填后端密钥，其余留空即可。

## 三、它做什么（7 步，人话）

1. **听懂问题** —— 判断属于哪一类：找企业、解释企业、企业对比、出拜访方案、还是普通闲聊（闲聊不查企业数据）。
2. **定上下文** —— 确认是哪家企业、哪一年；说不清就反过来问经理，不瞎猜。
3. **取事实** —— 调用数据库工具，拿企业画像、当年披露的原文、客户集中度、海外子公司等。
4. **取资料** —— 调用产品资料与地区资料，拿服务卡、适用条件与来源。
5. **做分析** —— 把上面的内容放在一起，分成五类说清楚：**已知事实 / 需求假设 / 候选服务 / 待核实事项 / 行动建议**。
6. **自检格式** —— 检查字段和引用格式是否合规（只做格式检查，不做事实判断）。
7. **返回结果** —— 输出一段 JSON 交给后端；后端校验通过后，网页上显示「回答文字 + 可点击的依据光球」。

## 四、它返回什么

一段结构化 JSON，包含：

- **回答文字块**：分为「事实」「需求假设」「候选服务」「待核实」「说明」几类，可直接显示给经理；
- **候选服务**：每项带推荐理由、依据引用、以及“条件是否已满足 / 待确认”的状态；
- **待核实事项**：资料里缺的东西（例如国别、进度、金额），明确列出来，不补 0 不编造；
- **拜访问题**：可直接拿去问客户的清单；
- **依据引用**：原文引用、产品卡引用等标识符，后端据此生成网页上的“光球”，点击可核查原文。

## 五、一个例子

经理在企业详情页问：**「这家公司值得关注什么？」**

工作流返回：

> 该企业 2023 年处于「出海扩张期」窗口（筹备层）；
> 当年披露了 2 条与市场开拓相关的动作（附原文引用，可点击核查）；
> 前五大客户集中度 76.8%，高于样本中位数；
> 规则命中的服务方向：账户方案、跨境结算架构、跨境人民币结算、汇率避险；
> 其中「账户方案」无前置条件，「跨境人民币结算」需先确认结算账户是否开立；
> 建议先问：贵司人民币结算账户是否已开立？主要结算币种与占比如何？

## 六、它不做什么（边界）

- 不自己算数字、不编企业名称与金额、不生成链接或网页代码；
- 拿不到资料时明确写「待核实」，而不是猜一个值；
- 不代替人工做授信审批、不自动联系客户；
- 企业比较只做同一年度，且不声称“哪家转化概率更高”。

## 七、谁在什么场景调用它

| 场景 | 调用方式 |
|---|---|
| 网页对话台提问 | 项目后端自动调用（自动带 `context_token`），经理无感知 |
| 工作流页试运行 | 手工填 `message` + `context_token`（用 `coze/examples/` 的合成样例） |
| 其他系统集成 | 由后端调用 `POST /v1/workflow/stream_run`，参数同上并在 Header 带访问令牌 |
